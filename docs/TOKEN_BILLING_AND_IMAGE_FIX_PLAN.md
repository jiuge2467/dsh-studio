## 一、 问题根因分析 (Root Cause Analysis)

### 1. Token 计费未统计 (显示 0 tok / ¥0.0000) 的根本原因
* **根因定位**：
  - 小鲸鱼姬桌宠通过 `mountPetToDom` 独立挂载在 `document.body` 根节点上。
  - DSH 的会话 Token 统计数据（`tokenUsage` 与 `liveTokenUsage`）是由 DSH 宿主在每个活跃会话的 React 上下文（如 `conversation.composer.dock` / `conversation.layout.overlay`）中通过 `useProjection` 动态下发的。
  - 之前的 `MascotPet` 独立挂载时未能直接接入 DSH 会话级 `useProjection` 管道，导致 `usage` 始终为 `undefined`，无法触发实时 Token 计算与累计。

### 2. 皮肤立绘切图边缘残留问题
* **根因定位**：
  - 原型图采用四象限设计稿（左上：正面、右上：侧面、左下：背面、右下：交互动作）。
  - 上一版 Canvas 裁切参数取样高度偏大（高度取了 45%），导致：
    1. **夏日水手服 (Summer Sailor)**：裁到了左下方背面视角的头部发顶；
    2. **赛博极客风 (Geek Style)**：边缘包含了右侧全息卡片与局部边缘元素。

### 3. 桌宠底部药丸状态条颜色过黑、对比度低
* **根因定位**：
  - 药丸状态条（`.statusPill`）使用了硬编码深黑背景（`rgba(15, 23, 42, 0.85)`），在浅色模式或多种皮肤下无法自适应，文字辨识度差。

### 方案 1：双轨接入 DSH 真实 Token 统计核心 (Token Billing Bridge)
1. **会话级数据探针 (Session Bridge)**：
   - 在 DSH 活跃会话插槽（`conversation.composer.dock`）注册无 UI 探针，提取官方 `useProjection('tokenUsage')` 与 `useProjection('liveTokenUsage')`。
   - 提取字段：`inputTokens` (未命中缓存)、`cacheReadTokens` (缓存命中)、`outputTokens` (生成Token)、`tokensPerSecond` (实时速率)。
2. **全局响应式 Store (Token Store)**：
   - 建立单例响应式事件总线，无论桌宠是在 DOM 还是 Slot 中，均可在有模型输出时**即时跳动刷新 Token 与金额**。
3. **精准计费算法 (DeepSeek V3/R1 官方价格阶梯)**：
   - 输入（未缓存）：¥1.00 / 百万 Token
   - 缓存读取：¥0.10 / 百万 Token (省 90%)
   - 输出：¥2.00 / 百万 Token

### 方案 3：状态药丸 UI 主题自适应设计 (Theme Adaptation)
重构 `.statusPill` 样式，全面接入 DSH 语义化 CSS 变量：
- **背景**：`background: var(--dsw-alias-bg-surface, rgba(255, 255, 255, 0.85))` + `backdrop-filter: blur(12px)`
- **边框**：`border: 1px solid var(--dsw-alias-border-subtle, rgba(0, 0, 0, 0.1))`
- **文字与费用**：
  - 费用数字：`color: var(--dsw-alias-color-success, #10b981)`（清晰翡翠绿）
  - 速度文本：`color: var(--dsw-alias-label-secondary, #6b7280)`
- **自适应效果**：在纯白浅色模式、深色模式、以及 10 款换肤主题（如 Windows XP、Cyberpunk 等）下均呈现高保真毛玻璃与高对比度文字。
