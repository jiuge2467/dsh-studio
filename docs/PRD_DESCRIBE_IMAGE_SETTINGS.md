> **文档性质**：Product Requirements Document (PRD)  
> **所属模块**：`@linxin666/dsh-tool-describe-image` (Client & Host) / Web UI Settings  
> **当前阶段**：Phase 1: PRD & Scope (PM)  
> **版本**：v1.0.0

## 1. 需求四问（Problem & Scope Framing）

| 维度 | 分析与定义 |
|:---|:---|
| **1. 目标用户 (Who)** | 使用 DeepSeek Harness Web GUI 的开发者与终端用户，需要为文本大模型接入多模态图像理解能力（如接入 OpenAI 4o、Claude 3.5 Sonnet、Qwen-VL、Xiaomi MIMO Vision 等视觉端点）。 |
| **2. 核心场景 (Where & When)** | 用户进入【设置】→【插件】→【图像理解】面板，配置自定义的视觉 API 接口地址、模型名、API Key 及协议参数，期望一键验证配置正确性并可靠保存。 |
| **3. 核心痛点 (Pain Points)** | 1. **保存必报“保存失败”**：分步写入与后端全量校验冲突、Secret 字段脱敏导致回读比对失败，阻断用户正常配置；<br>2. **模型 ID 盲填**：用户不知道第三方提供商支持哪些视觉模型，需去官网复制粘贴，容易填错（如填成 TTS/纯文本模型）；<br>3. **配置黑盒无反馈**：填完后无法得知接口是否调通、Key 是否有效，必须在对话中发送图片报错才发现配置错误，试错成本高。 |
| **4. 参考对象 (Reference)** | OpenAI/OneAPI 模型下拉与连通性测试面板、NextChat 自定义端点配置、DSH 官方 `llm.discoverModels` 探测机制。 |

### 2.1 P0 级核心功能清单
1. **F-1 设置保存底层修复**：
   - **后端宽容度校验**：重构 `installSettingsSection` 的 `validate` 钩子，支持单字段独立增量修改与阶段性补丁，避免因 `model` 或 `baseURL` 暂缺抛出异常阻断保存。
   - **Secret 字段安全解耦**：前端对 `role('secret')` 字段采用专用存储逻辑，跳过前端明文一致性比对，支持直接修改覆盖与密钥占位回显。
2. **F-2 模型列表自动拉取与下拉选择 (Model Discovery)**：
   - 在接口地址与 API Key 填写后，点击【获取模型】按钮（或在输入地址失焦时提示），通过后端中继或直连安全请求 `${baseURL}/models`。
   - 解析返回的 models 数组，提供可搜索可下拉的选择框（`Select/Combobox`），支持快捷选中与自定义输入。
3. **F-3 接口连通性一键测试 (Connectivity Ping)**：
   - 在卡片底部增加【测试连通性】按钮。
   - 发送 1x1 极小透明测试图片探测请求，验证：① 域名与网络可达性；② API Key 鉴权有效性；③ 模型名称与接口协议兼容性。
   - 渲染即时测试状态（进行中 Loading、成功 Success 耗时 ms、失败 Failure 错误码及清晰根因）。

## 4. EARS 格式验收标准（Acceptance Criteria）

### 4.1 Ubiquitous（通用性契约）
- **EARS-U-01**：系统应允许用户在不修改 `settings.yaml` 物理文件的前提下，通过 Web GUI 界面完整配置并保存 `describe_image` 所有有效参数。
- **EARS-U-02**：系统在传输与回显 API Key 时应始终进行脱敏防护，严禁在前端明文日志或普通 DOM 属性中暴露完整密钥。

### 4.2 Event-driven（事件驱动契约）
- **EARS-E-01**：**WHEN** 用户修改 `baseURL`、`model` 或 `apiKey` 并点击【保存】时，**THEN** 系统应原子化提交修改并立即持久化，界面提示“保存成功”，且不报 `model must be a non-empty model id` 或 `保存失败`。
- **EARS-E-02**：**WHEN** 用户填写有效 `baseURL` 与 `apiKey` 并点击【获取模型列表】时，**THEN** 系统应请求 `${baseURL}/models` 并在 3 秒内将可用模型填入下拉列表供用户一键点选。
- **EARS-E-03**：**WHEN** 用户点击【测试连通性】时，**THEN** 系统应使用当前表单中的草稿配置向目标端点发起最小化图像理解探测，并在按钮旁动态展示测试中、成功耗时或结构化错误信息。

### 4.3 State-driven（状态驱动契约）
- **EARS-S-01**：**WHILE** `baseURL` 为空或格式非合法 http/https URL 时，【获取模型列表】与【测试连通性】按钮应自动置灰禁用并给出输入提示。
- **EARS-S-02**：**WHILE** 连通性测试正在进行时，【测试连通性】按钮应呈现 Loading 旋转状态，且禁止重复触发点击。

### 4.4 Unwanted behavior（异常分支处理）
- **EARS-UB-01**：**IF** 用户填写的 API Key 无效或端点返回 401/403，**THEN** 连通性测试应明确显示 `[鉴权失败: 401 Unauthorized] 请检查 API Key 是否正确`，而不是抛出未捕获的空白异常。
- **EARS-UB-02**：**IF** 目标端点不存在或模型不支持视觉输入（如 400 Bad Request），**THEN** 测试结果应展示 `[模型错误: 400] 当前模型可能不支持图像输入或参数不兼容`。
